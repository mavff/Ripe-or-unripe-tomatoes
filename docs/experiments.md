# Training and evaluation guide

## AerialYield-T2M: measured CPU comparison

The dataset was prepared with `fruit-harvest data fetch-aerial` and `fruit-harvest data prepare-aerial --ripe-stage red`. Its 477/105/95 train/validation/test images are disjoint under the official COCO membership lists. Only `Red` (>90% red) maps to `ripe`. The source provides 105 ripe training objects, 21 in validation, and 14 in test. Two duplicate source labels were removed, leaving 10,050/1,937/2,201 processed objects. The [source audit](../output/aerial/metrics/source_split_audit.json) documents the repeated YOLO folder entries.

| Validation profile | Config | mAP@0.5 | Matched macro F1 | Matched ripe recall |
| --- | --- | ---: | ---: | ---: |
| 320 px, class weight power 0.25 | `aerial-cpu.yaml` | 38.4% | 55.5% | 0% |
| 320 px, class weight power 0.75 | `aerial-cpu-classweight.yaml` | 35.8% | 53.4% | 0% |
| 512 px, class weight power 0.50 | `aerial-cpu-highres.yaml` | **44.6%** | **57.7%** | 0% |

The [selection record](../output/aerial/metrics/validation_comparison.json) specifies the validation-only rule and selects `aerial-adamw-highres/weights/best.pt`. That run used 11 epochs, 512 px input, batch 4, a 0.4-hour CPU budget, AdamW, weight decay `0.0005`, cosine learning-rate decay, and weighted classification BCE. No validation run found a correct ripe harvest decision, so none produced `policy.json`.

The selected checkpoint was evaluated **once** on the 95-image test split with `--detection-only`: detection precision **80.0%**, recall **40.1%**, mAP@0.5 **47.4%**, and mAP@0.5:0.95 **32.1%**. Among 1,634 spatially matched fruits, classification accuracy was **94.3%** and macro F1 **59.3%**. The confusion matrix shows 13 matched ripe fruits classified as unripe (1) or semi-ripe (12); the remaining ripe fruit was missed. Thus ripe recall for the decision is **0%**. The published JSON, figure, and [PDF](../output/aerial/pdf/relatorio_tecnico_tomates.pdf) preserve the full numbers. The 14.0% class-specific ripe mAP integrates low-confidence predictions across thresholds; it does not imply a valid harvest decision at the project's 0.05 prediction floor.

To reproduce the selected run and test report, use the AerialYield commands in the [README](../README.md). The two 320 px profiles use `configs/aerial-cpu.yaml` with run name `aerial-adamw-cosine` and `configs/aerial-cpu-classweight.yaml` with run name `aerial-adamw-classweight`. Their validation outputs are `artifacts/evaluation/aerial-first-validation` and `artifacts/evaluation/aerial-classweight-validation`; the high-resolution validation output is `artifacts/evaluation/aerial-highres-validation`. Run `python scripts/compare_aerial_runs.py` after all three validations to regenerate the public comparison. Raw images and `.pt` weights remain local, so exact prediction replay requires retraining.

The first run fine-tunes COCO-pretrained YOLO11n on CPU. `configs/default.yaml` sets 512 px input, batch size 4, two data-loading workers, seed 42, early-stopping patience 7, and a two-hour maximum training time. Ultralytics' time setting is the hard budget and overrides its epoch count. Keep the run directory and configuration together when comparing later experiments.

The optimization profile explicitly uses AdamW with initial learning rate `0.001`, weight decay `0.0005`, and cosine learning-rate decay to `1%` of the initial rate. `class_weight_power: 0.25` applies partial inverse-frequency weights to Ultralytics' classification BCE. It helps counter class imbalance, but it is **not** Focal Loss or label-smoothing cross entropy, and it cannot create missing ripe examples. These values can be changed in the YAML file for a new run; use a new `--name` so the old run and its `args.yaml` remain available for comparison. The box and distribution-focal components of YOLO's detection loss remain as implemented upstream.

Run validation before test. Validation saves `policy.json` only if the model correctly identifies at least one ripe fruit; otherwise it reports `unavailable_no_ripe_true_positives`, and the model cannot be exported as a harvest bundle. Test evaluation of harvest decisions requires the saved policy and never retunes the threshold. The detector report includes per-class detection statistics in Ultralytics' output and aggregate mAP in `report.json`. The project report also includes a confusion matrix for spatially matched fruits and binary harvest precision, recall, and F1. A match requires IoU ≥ 0.5. Unmatched ripe predictions count as false harvest recommendations; missed ripe fruits count as missed harvest opportunities.

When validation cannot produce a policy, `evaluate --split test --detection-only` still measures held-out detection and matched-fruit classification without making any harvest recommendation. `matched_classification.accuracy`, precision, recall, and F1 apply only to fruits with a matched box at the stated IoU; inspect `ground_truth_objects` and `unmatched_predictions` alongside them. Detection mAP, precision, and recall remain separate metrics.

Read the results with the source imbalance in mind. AgRobTomato has only 30 fully ripe fruit annotations, including 11 in the prepared training split with seed 42. A larger, independently captured dataset is needed before relying on the recommendation for physical picking. Inspect the error examples in `report.json` and the plots generated by Ultralytics before changing thresholds or model size.

The short CPU verification run `smoke-adamw-cosine` used the same optimization profile with 320 px inputs and a 0.04-hour time limit. Its `args.yaml` records AdamW, `cos_lr=true`, and `cls_pw=0.25`; the training log reports class weights of about `0.426`, `0.775`, and `1.799`. It produced a checkpoint, but validation found no correct `ripe` decision among 14 ripe objects, so no harvest policy was generated. This smoke run checks that the pipeline executes; it is not a model-quality result for deployment.

For the future custom CNN, generate fruit crops from training images only, keep validation and test image identities unchanged, and compare maturity classification using macro F1 and per-class recall. Do not compare its crop accuracy directly with detector mAP.
